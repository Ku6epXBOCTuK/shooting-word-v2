# Статистика раундов

Сырьё для тюнинга баланса по живым данным. Каждый завершённый раунд пишется в
sqlite одним «снимком», по каналу. Данных пока мало, смотреть нечем — отсюда и
задачи на страницу в [backlog.md](./backlog.md).

## Когда пишется

Система `round-log` (группа `session`) накапливает счётчики, пока фаза
`PLAYING`, и на переходе `PLAYING` → следующая фаза отдаёт `RoundRecord` через
`ctx.onRoundEnd`. Виджет (`GameWidget.svelte`) отправляет его remote-командой
`reportRound` (`src/lib/features/widget/widget.remote.ts`) — только в полной
версии (`REWARDS_ENABLED` + uuid), в статической сборке отправки нет.

Раунды с `durationSec <= 0` не пишутся (зашли и сразу вышли).

## Поля

Тип и валидатор тела — `src/lib/features/rounds/record.ts`, таблица —
`src/lib/server/rounds/sqlite-adapter.ts` (18 колонок, индекс по
`(broadcaster_id, id)`, хвост обрезается до 1000 раундов на канал).

| Поле            | Что значит                                                        |
| --------------- | ----------------------------------------------------------------- |
| `startedAt`     | время входа в `PLAYING`, мс                                       |
| `durationSec`   | сколько секунд длился раунд                                       |
| `outcome`       | `wipe` (разрушены все корабли) или `empty` (зрителей не осталось) |
| `afk`           | раунд шёл в afk-режиме                                            |
| `viewers`       | зрителей на старте раунда                                         |
| `deaths`        | разрушений кораблей (не уникальных зрителей!)                     |
| `revives`       | возвратов кораблей                                                |
| `wordsSpawned`  | слов заспавнено за раунд                                          |
| `wordsExpired`  | слов, у которых истёк TTL и они выстрелили                        |
| `maxEnemies`    | пик живых слов на экране                                          |
| `kills`         | сбитых слов                                                       |
| `misses`        | промахов                                                          |
| `heals`         | ремонтов батареей (`!repair`)                                     |
| `doomsday`      | активаций doomsday device                                         |
| `avgEnemies`    | среднее число живых слов за раунд (по кадрам)                     |
| `avgHpFraction` | средняя доля hp живых кораблей от базовой (по кадрам)             |

## Инварианты

- `deaths` — это разрушения, а не зрители: возврат жетоном считается и
  разрушением, и возвратом, поэтому на вайпе `deaths = revives + viewers`.
- `kills` / `misses` / `heals` / `doomsday` — суммы по всем игрокам из
  `roundStats` (компонент на сессии).
- `avgHpFraction` считается по живым кораблям, разрушенные не учитываются.

## Чего нет

- Статистики по игрокам: `roundStats` живут только в виджете (баннер game over),
  в таблицу `rounds` не пишутся. Если понадобится топ игроков за раунд — нужна
  отдельная json-колонка.
- Данных в статической сборке (нет бэкенда).

## Как читать

```sh
sqlite3 data/app.db "select * from rounds order by id desc limit 50"
```

Чтения по HTTP нет: раунды пишутся виджетом и читаются напрямую из sqlite —
таблица `rounds`, индекс по `(broadcaster_id, id)`, до 1000 раундов на канал.
Канал определяется по `broadcaster_id`.
