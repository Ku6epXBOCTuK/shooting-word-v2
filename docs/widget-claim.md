# План: клейм uuid ключом (защита виджета от второго подключения)

Сохранено из обсуждения гонки между двумя виджетами (пункт в
[backlog.md](./backlog.md)). Пока не реализовано.

## Идея

Первый открывший ссылку виджета генерирует ключ (localStorage профиля) и
навсегда клаймит uuid за собой. Дальнейшие открытия uuid без ключа → экран
«ссылка занята, перегенерируй в кабинете». Ротация ссылки из кабинета убивает
старую пару uuid+key целиком. Лизинг с TTL не нужен — проверка статическая.

## Ограничения (accepted risk)

- утёкшая неклаймленная ссылка достаётся первому открывшему;
- две вкладки одного браузерного профиля делят ключ и обе пишут;
- если OBS не держит localStorage — после рестарта OBS стримеру придётся
  перегенерировать ссылку.
